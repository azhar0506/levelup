
Resilience & Self-Healing
- Components are expected to fail
- Design systems to recover automatically
- Self-healing reduces manual intervention 
- Replicas ensure desired state is maintained
- Failed components are automatically replaces


Automation
- Manual steps are discouraged 
- Automation enabled speed and agility
- Infrastructure and applications should be:
	- Reproducible 
	- Consistent
	- Frequently updated
- Automation reduced human error


Infrastructure as Code (IaC)
- Defined declaratively
- Enabled:
	- Consistency 
	- Repeatability 
	- Automation
- Essential for multi env deployments


CI/CD
- Continuous Integration:
	- Frequent code changes
	- Automated testing
- Continuous Delivery:
	- Code always ready for release
	- Release triggered by humans
- Continuous Deployment:
	- Automatic release to production
- Emphasis on:
	- Automated testing
	- Rollbacks
	- Monitoring


Secure by default
- Security built in from the start
- Zero Trust model:
	- Never trust, always verify
- Secure communication between components
- No implicit trust based on network location


Least Privilege
- Component get only required permissions
- Limits impact if compromised
- Reduced security blast radius


Speed, Efficiency & Cost
- Design for variable workloads
- Scale up during demand
- Scale down when idle
- Autoscaling improves efficiency
- Efficient design leads to cost savings


Service Discovery
- Avoid manual configuration 
- Services should be discovered automatically
- Applications dynamically locate dependencies
- Built-in discovery mechanisms preferred
