
What is Autoscaling
- Automatic scaling of applications or infrastructure
- Based on metrics or predefined rules
- Scales up, down, or across (Horizontal, Vertical)
- Reduces cost by avoiding unused resources
- Essential in cloud environments


Autoscaling Metrics
- Common metrics:
	- CPU
	- Memory
- Metrics depend on application needs
- Some workloads rely on specialised resources (e.g. GPU)


Autoscaling Approaches
- Reactive
	- Scales when thresholds are reached
	- Responds to real-time demand
	- May introduce short delays
- Scheduled
	- Scales at known times
	- Useful for predictable workloads
- Predictive
	- Uses historical data and ML
	- Scaled ahead of demand
	- More adaptive than scheduling


Scaling Types
- Vertical Scaling (Scale Up)
	- Increase resources on existing node
	- CPU, memory, disk
	- Easier in virtualised environment
	- Scaling down may require restart
- Horizontal Scaling (Scale Out)
	- Add or remove nodes or replicas
	- Preferred in cloud native systems
	- Improves resilience and availability 


Cloud Native View
- Emphasis on horizontal scaling
- Vertical scaling still useful in some cases
- Automation is critical for speed and consistency
- Efficient scaling leads to cost savings


Test Considerations
- Autoscaling must be tested
- Ensure performance under load
- Horizontal scaling increases:
	- Complexity
	- Data sharing challenges
	- Concurrency concerns


Kubernetes Autoscaling Tools
- Cluster Autoscaler
	- Scales cluster nodes based on demand
- HPA (Horizontal Pod Autoscaler)
	- Scales number of pod replicas
- VPA (Vertical Pod Autoscaler)
	- Scales pod resource requests/limits
- KEDA
	- Event-driven autoscaling 
	- Supports scale to zero
	- Important for cost efficiency
