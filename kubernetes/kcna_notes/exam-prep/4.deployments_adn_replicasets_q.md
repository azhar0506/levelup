### Which Kubernetes resource defines a group of one or more containers deployed together on the same host for scheduling and management purposes?

A Pod is the smallest deployable unit in Kubernetes and represents a group of one or more contaierns that share storage, network, and a specificatoin for how to run the contaiers. These containers are always scheduled together on the same node, making the Pod the fundamental unit for deployment and management

### Why would you choose to use a DaemonSet instead of a Deployment in a Kubernetes cluster?

A DaemonSet ensures that a copy of a specific pod is running on all (or a subset of) nodes in a Kubernetes cluster. This is useful for cluster-wide services like log collection, monitoring agents, or networking tools, where each node must have a running instance

### What is the function of Kubernetes Deployment?

A Kubernetes Deployment provides an object that delivers declarative updates for applications. With Deploymnets, you describe the desired state of you application (e.g., number of replicas, container images, ports), and the Deployment controller ensures that the actual state matches this description. This approach allows for easy rolling updates, scaling, and management of stateless or stateful applications

### What feature of Deployments ensures the number of Pods is as expected in case of a Pod crash or deletion?

Replication is a feature of Deployments that ensures a specified number of replicas are running at any given time. If a Pod crashes or is deleted for some reason, the Deployment contorller will automatically create a new replic to replace it, ensuring the desired state is maintained. 

### Which Kubernetes feature allows you to revert to an older version of an application during a problematic update?

Rollbacks are a Kubernetes feature that allows you to revert to a previous version of an application during a problematic update. If an update causes issues or doesn't work as expected, rollbacks enable you to quickly switch back to the previous version, minimising downtime and ensuring high availability

### When scaling the number of Deployment replicas, which command is used?

`kubectl scale` is a command used to update the number of replicas for a Deployment or other scalable resources. You can use this command to increase or decrease the number of replicas, and Kubernetes will automatically adjust the number of running Pods accordingly

### What does the maxSurge: 25% setting in the deployment strategy signify?

The maxSurge: 25% setting in the deployment signifies that Kubernetes can increase the number of Pods by up to 25% above the desired amount during an update. This allows for a temporary surge in replicas, which helps to minise downtime and ensure availability during rolling updates.

### What does the maxUnavailable: 25% setting in a Kubernetes Deployment strategy signify?

It signifies that up to 25% of the Pods can be unavailable during the update process. WHen you set maxUnavailable, you're telling Kubernetes how many Pods it's allowed to take down at any given time during an update. In this case, it means that you have total of 100 Pods running in your Deployment, Kubernetes will ensure that no more than 25 of them are unavailable (i.e., being update or terminated) at the same time

### What is the effect of changing the image of a Deployment?

Kubernetes creates a new ReplicaSet to manage the rollout of the updated application or service. The old replicaSet is scaled down to zero replicas, which the new one is scaled up to the desired number of replicas. This process ensures that there's no downtime for your application and allows for a smooth transition between versions.

### How can you monitor a Kubernetes Deployment's update in real time?

`kubectl rollout status deployment/<name>` - THe kubectl rollout status command allows you to monitor a Kubernetes Deployment;s update in real-time. By running this command, you can see the current state of the rollout including the number of replicas that have been updated and the overall progress of the deployment. 

### In case of a Deployment failure, which Kubernetes command can be used to revert to a functioning version?

`kubectl rollout undo deployment/<name>`

### What happens when you roll back to a specific revision of a Deployment?

Kubernetes reuses the original ReplicaSet and makes it the lates revision. The ReplicaSet is updated to reflect the changes from the previous revision, and the new revision becomes the current one.

### What happens when you delete a Kubernetes Deployment?

Both the Deployment itself and its associated ReplicaSets are deleted. This ensures that all resources related to the Deployment are removed, including any running replicas and their underlying pods.
