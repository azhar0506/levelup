### What is the main purpose of the Kubernetes API?

The kubernetes API provides a set of operations that can be used to create, read, update, and delete resources such as pods, services, and deployments. These operations are the foundation of how users and automated tools interact with a Kubernetes cluster.

### How do users typically interact with the Kubernetes API?

Using command-line tools like kubectl and Helm. These tools provide a user-friendly interace for managing Kubernetes resources, such as deploying applications, scaling deployments, and monitoring clsuter health. While it is possible to interact directly with the API endpoints or use third-party tools, command-line tools are the msot common and recommended way to interact with the Kubernetes API.

### Which component of Kubernetes uses the API to track the state of pods and nodes, and to schedule pods onto nodes?

kube-scheduler uses Kubernetes API to track the state of pods and nodes, and to schedule pods onto nodes based on resource availability and other constaints. It continuously monitors the cluster's state and makes decisions about where to place the new pods.

### What is the role of Admission Controllers in Kubernetes API?

Enforce policies and modify resources as part of processing requests. They act as gatekeepers, intercepting requests to the API serveer, and can either allow or reject hem based on predefined rules. This allows for fine-grained control over what objects are created, updated, or deleted within the cluster.

### If the --authorization-mode flag is not specified when starting the API server, what default mode does the Kubernetes API server use?

Defaults to AlwaysAllow mode, which allows all requests to be authorized without any restrictions. This mode is not recommended for production environments as it bypasses all authorisation checks.

### What feature allows you to extend the Kubernetes API by defining new resource types?

Customer Resource Definitions (CRD) These deifnitions essentially tell the Kubernetes API server how to handle new kind of resources that are not part of the standard Kubernetes API. By creating a CTD, you can add new endpoints to the API server, which then allows for the creation and management of these custom resources.

### In the path a request to the Kubernetes API follows, which step occurs immediately after Authorization?

Admission Control - whcih is a process that hcecks if the request should be allowed to proceed based on certain policies and rules.

### What would be a potential use case for an Admission Controller in a Kubernetes cluster?

Enforcing a policy that a certain namespace doesn't exceed a given memory threshold is a potential use case for an Admission Controller. This would involve writing a customer admission controller that checks the total memory usage of all pods in a namespace against a predefined limit.

### If you want to quickly list all available API resources in your current Kubernetes cluster from the command line, which command would you use?

```sh
kubectl api-resources
```

### What are the three crucial stages that a request to the Kubernetes API goes through in the context of security and policy enforcement?

The first stage is Authentication, where the identitity of the user service making the request is verified. The second stage is Authorisation, where the authenticated user's permissions are checked to ensure they have the necessary rights to perform the requested action. The third and final stage is Admission Control, where additional checks and validation are performed on the request, such as quota checks, security context contraints, and other admission controllers.

### How does the kubectl proxy command in Kubernetes handle API server authentication?

Automatically handles authentication with the API server by using the existing authentication configuration, such as the kubeconfig file or service account tokens. This allows users to access teh API server without having to manually authenticate each time.
