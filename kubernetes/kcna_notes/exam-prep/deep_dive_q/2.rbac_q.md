### What is the purpose of Role Based Access Control (RBAC) in Kubernetes?

Designed to assign specfic roles to users and groups, allowing adminitrators to control who has access to which resources within a cluster. By defining roles and assigning them to suers or groups, RBAC enables fine-grained access control and helps prevent unauthroized access to sensitive resources.

### What does the kubeconfig file contain?

Contains both cluster details, such as the API server URL, certificate authority data, and authentication credentials, as well as user information, including the username, client certificate, an private key. This allows users to authenticate with multiple clusters and switch between them seamlessly.

### What is the purpose of Certificate Authority (CA) in Kubernetes?

The CA is responsible for creating and verifying certificates wihtin the cluster. The CA issues certificates to components such as pods, services, and noes, allowing them to securely communicate with each other. The CA also verifies the identitiy of these components by checking their certificates.

### How are Users and Groups typically managed in Kubernetes?

Managed externally through mechanisms such as client certificates signed by a Certificate Authority (CA) or tokens that can be obtained fro an external source. These external sources provie the necessary credentials to authenticate users and authorise access to cluster resources.

### What does a ClusterRole in Kubernetes define?

Defines permissions that apply to cluster-scoped resources (e.g., noes) or namespaced resources across all namespaces, enabling access control at the cluster level, according to authoritative Kubernetes documentation.

### A development team requires write access to the 'dev-ns' namespace for their application deployments, but should not have permissions elsewhere in the cluster. What is the correct RBAC approach to grant this namespace-specific access to the team's service accounts?

In Kubernetes RBAC, a Role defines namespace-scoped permissions, such as write access in 'dev-ns', an RoleBinding binds this Role to specific subjects like service acconuts, ensuring they have the required access only within that namespace an nowhere else in the cluster.

### What does the command `kubectl auth can-i` check?

Checks if the user has permissions to perform any action on any resource. It uses the RBC system to verify the user's permissions

### In Kubernetes, how do Role objects differ from ClusterRole objects in terms of scope?

Roles are namespacced resources in Kuebrnetes, meaning they only grant permissions within the specfic namespace where they are defined, while ClusterRoles are cluster-scoped and can efine permissions across multiple namespaces or for non-namespaced resources.

### How are permissions assigned to a user in Kubernetes using RBAC?

Permissions are assigned to users through their membership in a group or by being explicitly mentioned in a RoleBinding or ClusterRoleBinding. A ClusterRoleBinding grants the permissions defined in a ClusterRole to a user or group for all namespaces in the cluster

### How should a Kubernetes pod securely obtain API server access without relying on personal user credentials?

Kubernetes documentation mandates ServiceAccounts for pod authentication to the API server. Creating a dedicated ServiceAccount with RBAC policies ensures least-privilege access, isolates permissions to specific pods, and avoid reliance on personal credentials by ising automatically mounted tokens.

### When configuring a Pod to authenticate with the Kubernetes API using a ServiceAccount, how is the authentication token securely delivered to the container?

Kubernetes automatically creates a Secret for each ServiceAccount containing the authentication token. This Secret is mounted as a read-only volume at /var/run/secrets/kubernetes.io/serviceaccount in the container, as documented in Kubernetes official authentication mechanisms.

### When implementing least-privilege access in Kubernetes, which characteristic distinguishes a ClusterRole from a Role in multi-namespace environments?

ClusterRoles allow permissions to be defined once and bound in multipple namespaces using RoleBindings, facilitating centralised management and reducing redunancy, which support least-privilege access by minimising configuration errors and ensuring consistent permissions across namespaces.
