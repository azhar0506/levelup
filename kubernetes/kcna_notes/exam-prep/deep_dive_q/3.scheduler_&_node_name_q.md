### What is the primary function of the kube-scheduler in Kubernetes?

To schedule application in the form of pods to run on various nodes in the Kubernetes cluster. It takes into account factors such as resource availability, node affinity, and pod priority when making scheduling decisions.

### What happens during the "Filtering" stage of the Kube-Scheduler's process?

Kube-Scheduler narrows down the list of available nodes by checking which one meet the pod's resource requests, constraints (like taints, tolerations, and node selectors), and other scheduling rules. Only nodes that pass these checks move forward to the next stage.

### What is the purpose of the schedulerName field in a pod's specification

To specify which scheduler will hanle the scheduling of the pod. By default, Kubernetes uses its built-in scheduler, but this field allows the use of custom schedulers.

### What does the nodeName field in a pod specification indicate?

The nodeName field in a pod specifcation is used to explicitly assign the pod to a specific node by name, bypassing the default sheduler and ensuring it runs on that node if resources permit

### What is the role of the nodeSelector field in a pod's specification?

To specify a set of labels that must be present on a node for a pod to be scheduled on that node. By using this field, you can ensure that your pods are deployed on nodes with specific characteristics, sich as particular hardware configurations or network properties

### How can you ensure a Kubernetes pod is scheduled exclusively on nodes labeled with 'gpu:nvidia'?

The nodeSelector field in the pod specification key-value pairs that must match node labels, ensuring the pod is scheduled only on noes with the label gpu:nvidia.
