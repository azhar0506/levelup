### What is the smallest deployable unit of compute in Kubernetes

A Pod is the smallest deployable unit of compute in Kubernetes, It represetns a single instance of an applciation or service, compromising one or more containers that share the same network namespace, storage resources, and life cycle. Pods are ephemeral and can be created, scaled, and deleted as needed.

### How do you check the status of pods running Kubernetes?

`kubectl get pods` - The output includes details like Pod name, namespace, IP address, creation timestamp, the current phase (Running, Pending, Succeeded, Failed)

### How do you view the logs of a specific pod in Kubernetes?

`kubectl logs` - Used to retrieve and display logs of a specifc Pod in Kubernetes. You can use tis command to view the output of containers running within the Pod

### What is the command to create a port-forward tunnel in Kubernetes for testing purposes?

`kubectl port-forward pod/<pod_name><local_port>:<pod_port>` - The kubectl port-forward command is used to forward traffic from a local port to a pod's port in a Kubernetes cluster, creating a tunnel for testing purposes. This allows developers to test their applciations without exposing them to the external network.


### How do you run a command inside a specific container in a running pod?

`kubectl exec -it <pod_name> -c <container_name> -- <command>` - The kubectl exec command is used to execute a command inside a specifc container in a running pod. The -it flag allow for interactive shell access, and the -c flag specifies the container name. The -- seperator is used to seperate the command from arguments.

### How can you see logs of a particular container from a multi-container pod?

`kubectl logs <pod_name> -c <container_name>` - The kubectl logs command can be used with the -c or --container flag to specify a particular container within a multi-container pod. This allows you to view logs only for that specific container.

### Which command would you use to view the logs of a container that has crashed and restarted?

`kubectl logs pod/<pod_name> -c <container_name> -p` - The -p flag stands for --previous, which tells Kubernetes to show the logs from the previous container instance, rather than the current one. When a container crashes and restarts, its logs are preserved and can be viewed using this flag. 

### What is the Kubernetes object YAML configuration management command that provides a declarative approach?

`kubectl apply -f <config_file.yaml>` - This allows you to describe the desired state of your resources using YAML config files. When you run apply, Kubernetes will ensure that the current state matches the desired state described in the YAML file, either by creating new resources or updating existing ones. 

### How do you run a pod with a specifc image in Kubernetes?

`kubectl run nginx --image=nginx` - creates a new pod with a container running the specifie dimage. The run command provides a simple way to create a pod with specific image without having to write a detailed YAML configuration

### In Kubernetes, what is the purpose of a sidecar container in a pod?

This is a secondary container that runs alongside the main container in a pod, typically performing a specifc task that complements or enhances the functionality of the main container. Examples include logging, monitoring, or proxying traffic to the main container.

### What Linux namespace is the default shared in a Kubernetes Pod?

The Network namespace is the default shared namespace in a Kubernetes Pod. All containers in a pod share the same network namespace, which means they share the same IP address and port space. This allows them to communicate with each other as if they were on the same host.


### What does the Kubernetes network model allow pods to do in terms of communication and NAT?

Allows pods to communicate with each other directly, wihtout the need for NAT. In a kubernetes cluster, each pod has its own IP address, and all pods can communicate with each otehr using these IP addresses

### In a Kubernetes Pod, what is used to run tasks that must complete successfully before the main application containers start?

Init containers are specialised containers in a Pod that run before the main application containers start. They are designed to perform initialisation tasks, such as setting up environment variables, creating directories, or waiting for dependencies to become available. If an Init Container fails, the Pod will not startm ensuring that the main application containers only begin running once all necessary prerequireistes have been met.
