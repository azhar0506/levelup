### What are Kubernetes Services?

A Kubernetes Service provides a stable network endpoint (IP/DNS) to access a dynamic set of Pods and load-balances traffic between them, even as Pods are created or destroyed. It decouples how you reach an application from where the Pods are actually running.

### How Services can be used for Service Discovery

Kubernetes Services enable service discovery by providing a stable DNS name for an application. Pods communicate using this name, and Kubernetes automatically routes and load-balances traffic to the correct Pods as they change.

### How Endpoints relate to Kubernetes Services

Endpoints are the concrete link between a Service and its Pods. A Service uses label selectors to identify Pods, and Kubernetes creates an Endpoints object that contains the IP addresses and ports of those Pods, which is what traffic is actually sent to.

### How DNS names relate to Kubernetes Namespaces

Kubernetes DNS names are scoped to namespaces. A Service’s full DNS name includes its namespace, so Services with the same name can exist in different namespaces without conflict.

### How we can conveniently check DNS using throwaway Pods

We use throwaway Pods to test Kubernetes DNS from inside the cluster and verify that Service names resolve correctly.

### Explain the relationship of EndpointSlices to Pods (Service → EndpointSlice → Pod)

EndpointSlices are the scalable link between Services and Pods. A Service selects Pods by labels, Kubernetes groups the matching Pod IPs into EndpointSlices, and traffic is then routed to those Pods.

### Which Kubernetes component provides a way to expose an application running on a set of Pods as a network service?

Service provides a way to expose an application running on a set of Pods as a network service by providing a stable IP address and DNS name that cna be used to access the application from outside the cluster or from other pods wihtin the cluster. Services are an abstraction that defines a logical set of pods and a policy by which to access them.

### What is the default service in Kubernetes that establishes a service with an internal IP address, reachable only within the cluster?

ClusterIP is the default service type in Kubernetes that establishes a service with an internap IP address, which is reachable only within the cluster. When a Pod is created, Kubernetes automatically assigns it a ClusterIP, making it accessible from other Pods and services within the same cluster.

### Which Kubernetes service type allows service to be technically available outside of the cluster, if your nodes IP address are externally accessible?

NodePort is a type of service in Kubernetes that allocates a port on each nodee's IP address, allowing external traffic to reach the service if the nodes IP addresses are externally accessible. By doing so, services become technically available outside of the cluster, although it still depoends on the specific network configuration and security policies

### What is the service type in Kubernetes that creats what would be in DNS terms, a CNAME, i.e. an alias of another domain

ExternalName is a type of service in Kubernetes that creates an alias for DNS name or a URL, effectively creating a CNAME record. This allows a service to be accessed through an alternate name, which can be useful for redirecting traffic or providing a more user-friendly interface.

### What is a "Headless" service in Kubernetes?

A Headless service in Kubernetes is indeed a ClusterIP service that has no IP allcoated to it. By doing so, it allows direct access to Pods without going through a service's IP address. Instead, clients can use DNS or environemtnal variables to find and communciate with the Pods directly.

### Which Kubernetes service type is dependent on your Kubernetes offering and may vary significantly between On-Prem and Cloud?

LoadBalancer depends heavily on the underlying infrastructure and Kubernetes offering. In cloud environemnts liek AWS or GCP, LoadBalancer services can integrate with native load balancers provided by the cloud provider. However, in on-premises environments, the implementation may be different, using software-based load balancers or other custom solutions.

### Which Kubernetes service is only accessible within the cluster?

ClusterIP. It does not provide any mechanism for external access, making it suitable for services that need to communicate with other components within the same cluster.

### What do EndPoints in Kubernetes represent?

Endpoints in Kubernetes represent the IP address and ports assigned to the individual pods that a service points to. When a service is created, Kubernetes automatically creates an EndPoint object that container the IP addresses and ports of the pods that match the service's selector criteria. This allows the service to forward traffic to the correct pods.

### What does the command `kubectl expose` do in Kubernetes?

It creates a new Kubernetes Service object that exposes a deployment (or other resources like ReplicaSet or Pod) as a network service. By doing so, it makes the deployment accessible through a stable IP address and port number within the cluster

### What is the primary use case of a ClusterIP service in Kubernetes?

It establishes a service with an internap IP address, reachable to only within the cluster. By creating a ClusterIP service, you can provide a stable network identity (IP address and port number) for your applciaiton that can be used by other pods or services withing the same cluster.

### What is the function of a LoadBalaner service type in Kubernetes?

Its to provide a mechanism for automatic load distribution across multiple nodes and pods. By creating a LoadBalancer service, you can distribute incoming traffic across multiple replicas of your application, ensuring that no single node or pod becomes overwhelmed with requests.

### A pod running in the payments namespace needs to call an HTTP service named orders that is defined in the abckend namespace. Assuming default cluster DNS configuration, which statement best describeshow the pod should use DNS to reach this Service?

Kubernetes DNS allows cross-namespace resolution by using the Service's namespace in the DNS name. The fully qualified name is `orders.backend.svc.cluster.local`, and the shorter form `orders.backend` is resolveable because the DNS search path include `svc.cluster.local` and the resolver will try the appropriate suffixes.

### What is the distinguishing feature of a Headless service in Kubernetes?

It provides a DNS implementation with no proxy, so each pod handles its own traffic. By creating a Headless service, you can ensure that each pod receives its own IP address and handles incoming request deireclty, without relying on a proxy or a load balanceer

### What is the key funcitonal distinction between a ClusterIP and a NodePort service in Kubernetes?

ClusterIP services expose the service on a cluster-internal IP, making them accessible only within the cluster, while NodePort services expose the service on each nod's IP at a static port, allowing external traffic to access the servie from outside the cluster.

### From an implementation perspective, how does Kubernetes typically perform load balancing for a Service inside the cluster?

Kubernetes uses kube-proxy running on nodes to configure iptables or IPVS rules that translate traffic from the virtual Service IP and port to one fo the backing Pod IPs, effectively achieving load balancing across those endpoints

### How would you specifcally define a Headless Service in a Kubernetes YAML specification?

By setting `spec.clusterIP: None` in the Service YAML specification. This tells Kubernetes not to assign an IP address to the service and instead return the DNS entries for the pods that match the selector. By doing so, clients can then directly accress the pods without going through the service's load balancer

Creating a temporary busybox Pod in the same namespace and running dig or nslookup from inside it validates the DNS configuration and service discovery  exactly as the application Pods experience it, including namespace-specific search domains
