### What is the purpose of using Kubernetes Secrets?

Are used to store and manage sensitive information such as passwords, tokens, keys, and other confidential data that should not be exposed in plain text. This allows for secure storage and retrieval of sensitive data by applicaiton running on a Kubernetes cluster

### What is the difference between a Secret and a ConfigMap in Kubernetes?

Secrets are used to store confidential information such as passwords, API keys, or certificates, while ConfigMaps are used to store non-secret configuration data such as environment varaibles, port numebrs, or other application settings. The main difference between the two is that Secrets are encrypted at rest and in transite, whereas ConfigMaps are not.

### How is the sensitive data stored in Kubernetes Secrets?

Secrets are stored as base64-encoded strings. When you create a Secret, Kubernetes encodes the data using base64 encoding, which converts binary data into a text format that can be safely stored and transmitted. While this doesn't provide strong security gaurentees like encryption would, it does probvide some level of protection against accidental exposure.

### What is the encoding mechanism used in Kubernetes Secrets?

Base64

### What is the potential risk when using secrets in Kubernetes?

In Kubernetes, secrets are stored in etcd, which is a distributed key-value store. While secrets are encoded in base64 format, if someone gains access to etcd or retrieves the secret as YAML, they can easilt decode the value adn obtain sensitive infomration such as passwords, API keys, or certificates.

### What command is used to create a secret in Kubernetes?

```sh
kubectl create secret
```

### What type is assigned when creating a generic secret in Kubernetes?

Opaque. 
- This signifies that the secrets content are not specific to any particular type or format, making it a catch-all for secrets that don't fit into other predefined categories

### Which kubectl command is used to create a TLS secret that includes both the certificate file and its corresponding private key?

```sh
kubectl create secret tls web-secret --cert=webserver.crt --key=webserver.key
```

### What describes how cert-manager provides TLS certificates to applications in Kubernetes?

cert-manager automates TLS certificate management by creating and updating Kubernetes Secrets with certificate data, which are then referenced by Ingress resources or directly mounted into application Pods
