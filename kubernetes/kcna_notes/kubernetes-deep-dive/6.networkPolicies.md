# Network Policies

## What are NetworkPolicies

NetworkPolicies are Kubernetes resources used to control network traffic between Pods.

By default, Kubernetes networking is open:
•	Any Pod can talk to any other Pod
•	Any Pod can access any Service

This is fine for:
•	Learning clusters
•	Small, trusted environments

But it’s not ideal for:
•	Multi-tenant clusters
•	Security-sensitive workloads
•	Zero-trust designs

NetworkPolicies allow you to explicitly define which traffic is allowed.

## Purpose of NetworkPolicies

NetworkPolicies let you:
•	Isolate Pods by default
•	Allow traffic only from:
	•	Specific Pods (via labels)
	•	Specific Namespaces
	•	Specific IP blocks
•	Control:
	•	Ingress (incoming traffic)
	•	Egress (outgoing traffic)

Once a Pod is selected by a NetworkPolicy, only explicitly allowed traffic is permitted.


## How NetworkPolicies Work

A NetworkPolicy consists of:
•	podSelector – selects which Pods the policy applies to
•	policyTypes – Ingress, Egress, or both
•	rules – define allowed traffic

Important concept:

    NetworkPolicies are deny-by-default once applied

If no rule allows traffic → traffic is blocked.


## Label-Based Traffic Control

NetworkPolicies rely heavily on labels.

Example logic:
•	Allow ingress only from Pods with label run: nginx
•	Pods without matching labels are blocked

This enables:
•	Fine-grained Pod-to-Pod communication control
•	Logical security boundaries inside the cluster


## Example Behaviour (Conceptual)

An nginx Pod is exposed via a ClusterIP Service
Without NetworkPolicies:
    •	Any Pod (e.g. curl) can access it
•	With a NetworkPolicy applied:
	•	Only Pods with matching labels are allowed
	•	Other Pods are denied, even though DNS still resolves

DNS resolution ≠ network access.

## Policies Are Cumulative (

•	Multiple NetworkPolicies can apply to the same Pod
•	Policies are added together
•	The effective policy is the union of all policies

If any policy allows traffic, that traffic is allowed.

There is no “deny” rule in NetworkPolicies — only allow rules.

Now, we will implement a Network Policy to restrict access to the nginx pod. Network Policies in Kubernetes allow you to control the flow of traffic. We will create a policy that allows access to the nginx pod only from pods with specific labels. Start by creating a network policy configuration file named 'networkpolicy.yaml'


```sh
cat <<EOF > networkpolicy.yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-nginx-access
  namespace: default
spec:
  podSelector:
    matchLabels:
      run: nginx
  policyTypes:
    - Ingress
  ingress:
    - from:
      - podSelector:
          matchLabels:
            run: curl
EOF
```

Apply the network policy to your cluster. This will enforce the rules defined in the policy, restricting the access to the nginx pod as specified. Run the following command to apply the network policy

```sh
kubectl apply -f networkpolicy.yaml
```

Output:

```sh
networkpolicy.networking.k8s.io/allow-nginx-access created
```

Test the network policy. Start another curl pod which we'll be using to accessing the nginx service again. Since this pod has the label 'run:curl', it should be allowed by the network policy. Run the following command to start an interactive session in a new curl pod

