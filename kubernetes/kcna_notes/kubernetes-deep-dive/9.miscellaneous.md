# Kubernetes Miscellaneous

### What Happens When a Node Fails

Node Failure Basics
•	Nodes regularly report health via the kubelet
•	If the kubelet stops reporting:
	•	The node becomes NotReady
	•	Internally, the node condition becomes Unknown

What Happens to Pods
•	Existing Pods may continue running on the failed node
•	Kubernetes does not immediately kill or move them
•	After ~5 minutes, the Node Controller:
	•	Evicts Pods
	•	Reschedules them onto healthy nodes

### Why Pods Can Get Stuck in Terminating 

You do not need to debug this for KCNA, but understand the idea:
•	If the node is unreachable:
	•	Kubernetes cannot talk to the kubelet
	•	Pod termination cannot complete
•	Pod stays in Terminating until the node responds again

### Kubernetes Garbage Collection (GC)

Garbage Collection is Kubernetes’ automatic cleanup mechanism.

It removes:
	•	Terminated Pods
	•	Completed Jobs
	•	Orphaned resources (no owner)
	•	Dynamically provisioned PVs (with ReclaimPolicy: Delete)
	•	Expired CSRs
	•	Deleted Nodes (cloud environments)
	•	Unused containers and images

### Probes

Types of Probes
•	Liveness Probe
	•	Checks if container is alive
	•	Failure → container restarted
•	Readiness Probe
	•	Checks if container can receive traffic
	•	Failure → removed from Service endpoints
•	Startup Probe
	•	Checks if app has started
	•	Pauses liveness/readiness until successful
