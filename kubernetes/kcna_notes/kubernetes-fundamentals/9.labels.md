### Labels

- Fundeamental for identifying and organising resources
- Effective mechanism for assigning metadata to a Kubernetes Object
- Useful for tagging resources
- Group related resources together
- Kubernetes uses labels and label selectors for service discovery. load balancing, and network policies
- Network policies can use label selectors to define rules for how pods can communicate with each other
- Labels can also be used to create scopes or environments within a Kubernetes cluster
- You could use labels to designate resources as belonging to a certain group (dev, test, prod)

### Lab

Show the yaml output for an nginx pod, note the default label of 'run:nginx':

```sh
kubectl run nginx --image nginx --port 80 -o yaml --dry-run=client
```

Output:

```sh
apiVersion: v1
kind: Pod
metadata:
  creationTimestamp: null
  labels:
    run: nginx
  name: nginx
spec:
  containers:
  - image: nginx
    name: nginx
    ports:
    - containerPort: 80
    resources: {}
  dnsPolicy: ClusterFirst
  restartPolicy: Always
status: {}
```

And let's run this:

```sh
kubectl run nginx --image nginx --port 80
```

Output:

```sh
pod/nginx created
```

Review the yaml for exposing this pod, note that the selector references 'run:nginx' which is how it matches our pod

```sh
kubectl expose pod/nginx --dry-run=client -o yaml
```

Output:

```sh
apiVersion: v1
kind: Service
metadata:
  creationTimestamp: null
  labels:
    run: nginx
  name: nginx
spec:
  ports:
  - port: 80
    protocol: TCP
    targetPort: 80
  selector:
    run: nginx
status:
  loadBalancer: {}
```

We'll also run this:

```sh
kubectl expose pod/nginx
```

Output:

```sh
service/nginx exposed
```


With these labels set, we could query these using a selector parameter


```sh
kubectl get all --selector run=nginx
```

Output:

```sh
NAME        READY   STATUS    RESTARTS   AGE
pod/nginx   1/1     Running   0          3m26s

NAME            TYPE        CLUSTER-IP     EXTERNAL-IP   PORT(S)   AGE
service/nginx   ClusterIP   10.43.116.93   <none>        80/TCP    28s
```

Let's try out labels ourselves, we will create three pods, each with a specific colour as a label. The following yaml will be used as a template to create these (longer pastes like this may not appear to work as expected but, if you review the file they will be okay)


```sh
cat <<EOF > coloured_pods.yaml
apiVersion: v1
kind: Pod
metadata:
  creationTimestamp: null
  labels:
    run: ubuntu
    colour: red
  name: ubuntu-red
spec:
  containers:
  - command:
    - sleep
    - infinity
    image: ubuntu
    name: ubuntu
    resources: {}
  dnsPolicy: ClusterFirst
  restartPolicy: Always
status: {}
---
apiVersion: v1
kind: Pod
metadata:
  creationTimestamp: null
  labels:
    run: ubuntu
    colour: green
  name: ubuntu-green
spec:
  containers:
  - command:
    - sleep
    - infinity
    image: ubuntu
    name: ubuntu
    resources: {}
  dnsPolicy: ClusterFirst
  restartPolicy: Always
status: {}
---
apiVersion: v1
kind: Pod
metadata:
  creationTimestamp: null
  labels:
    run: ubuntu
    colour: pink
  name: ubuntu-pink
spec:
  containers:
  - command:
    - sleep
    - infinity
    image: ubuntu
    name: ubuntu
    resources: {}
  dnsPolicy: ClusterFirst
  restartPolicy: Always
status: {}
EOF
```


We'll apply this and create our pods

```sh
kubectl apply -f coloured_pods.yaml
```

Output:

```sh
pod/ubuntu-red created
pod/ubuntu-green created
pod/ubuntu-pink created
```

If we check we will have our coloured pods in the output

```sh
kubectl get pods -o wide
```

Output:

```sh
NAME           READY   STATUS    RESTARTS   AGE   IP          NODE       NOMINATED NODE   READINESS GATES
nginx          1/1     Running   0          12m   10.42.2.2   worker-1   <none>           <none>
ubuntu-green   1/1     Running   0          33s   10.42.1.3   worker-2   <none>           <none>
ubuntu-pink    1/1     Running   0          33s   10.42.2.3   worker-1   <none>           <none>
ubuntu-red     1/1     Running   0          33s   10.42.1.2   worker-2   <none>           <none>
```


And now if we desire, we can specifically select resources based on that selector 

```sh
kubectl get all --selector colour=green
```

```sh
NAME               READY   STATUS    RESTARTS   AGE
pod/ubuntu-green   1/1     Running   0          86s
```

We can also use the shorthand method of -l which is a synonym for --selector

```sh
kubectl get all -l colour=green
```

Output:

```sh
NAME               READY   STATUS    RESTARTS   AGE
pod/ubuntu-green   1/1     Running   0          2m
```

Let's cleanup after ourselves

```sh
kubectl delete pod/nginx service/nginx pod/ubuntu-red pod/ubuntu-green pod/ubuntu-pink --now

rm coloured_pods.yaml
```
