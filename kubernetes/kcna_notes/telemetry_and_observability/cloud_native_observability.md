# Cloud Native Observability

## What is Observability

Observability is the ability to understand the state of a system by examining its outputs (telemetry).

Telemetry comes from:
•	Applications
•	Containers
•	Nodes
•	Infrastructure

High-quality telemetry = better troubleshooting and reliability.

## The 3 Pillars of Cloud Native Observability

Logs:

What they are
•	Text-based records of events
•	Generated by applications and systems

Why you use them
•	Debugging
•	Understanding what happened
•	Error investigation

Metrics:

What they are
•	Numeric measurements collected over time
•	Time-series data

Why you use them
•	Performance monitoring
•	Capacity planning
•	Detecting abnormal behaviour

Traces:

What they are
•	Track a request as it moves through multiple services

Why you use them
•	Understanding request flow
•	Diagnosing latency issues
•	Debugging distributed systems


## Types of Metrics 

Gauges
•	Current value at a point in time
•	Example: memory usage, CPU usage

Counters
•	Only increase over time
•	Example: number of requests, errors

Meters
•	Rate of events over time
•	Example: requests per second

Histograms
•	Distribution of values in buckets
•	Example: request latency ranges

## Alerting and the 3 Pillars

Alerts are triggered by:
	•	Metrics
	•	Logs
	•	Traces
Alerts notify teams of anomalies or failures

## kubectl top 

You should be aware that:
	•	kubectl top displays basic metrics
•	Commonly shows:
	•	CPU usage
	•	Memory usage
•	Requires metrics infrastructure (e.g. metrics server)
